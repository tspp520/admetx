# admetx — 审计日志 & 应急账号

> 2026-05-26 引入 audit_log 表 + 30 天"记住我" + 应急本地账号约定。

## 审计日志 `audit_log`

每次认证相关动作都会写一行。**不会因为审计失败拖垮主请求**（audit 写库失败只打日志）。

### Schema

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | serial | PK |
| `user_id` | int | 关联 users.id，可为空（如未知用户尝试登录） |
| `username` | varchar(64) | 输入的用户名（即使用户不存在也记录） |
| `action` | varchar(32) | `login` / `login_failed` / `logout` / `password_change` / `user_created` |
| `auth_source` | varchar(16) | `local` / `ldap`（LDAP 接入后填 ldap） |
| `ip` | varchar(64) | 优先 `x-forwarded-for`，否则 `x-real-ip` |
| `user_agent` | varchar(256) | 浏览器 UA（截断到 256） |
| `detail` | jsonb | 自由字段，如 `{reason:'bad_password'}`、`{rememberMe:true}` |
| `created_at` | timestamptz | 自动 now() |

索引：`(user_id, created_at)`、`(action, created_at)`。

### 常用查询

```sql
-- 最近 50 条认证事件
SELECT created_at, username, action, auth_source, ip FROM audit_log
ORDER BY created_at DESC LIMIT 50;

-- 某用户的所有登录记录
SELECT created_at, action, ip, detail FROM audit_log
WHERE username = 'cp12398' ORDER BY created_at DESC;

-- 24h 内失败登录次数（按用户名 + IP 聚合）
SELECT username, ip, COUNT(*) FROM audit_log
WHERE action = 'login_failed' AND created_at > now() - interval '24 hours'
GROUP BY 1, 2 ORDER BY 3 DESC;
```

## 30 天"记住我"

登录页有「记住我（30 天内免登录）」复选框：
- 不勾：JWT TTL = 24 小时（默认）
- 勾上：JWT TTL = 30 天

实现位于 `lib/auth.ts` 的 `TTL_SHORT_SEC` / `TTL_LONG_SEC` 常量；签发时传 `signJwt(claims, ttlSec)`，cookie 的 `maxAge` 与 JWT exp 对齐。

## 应急账号约定（LDAP 挂时的兜底）

LDAP 接入后，**保留至少 1 个本地 bcrypt 账号**作为应急通道。当前约定：

| 用途 | 用户名 | 来源 | 注意 |
| --- | --- | --- | --- |
| 应急 admin | `admin` | seed 脚本 (`lib/db/seed.ts`) | 部署后**必须**改密码（设置页一键改） |
| 临时测试 | `cp12398` | 手动 SQL 插入 | 上线 LDAP 后可删 |

应急账号 `auth_source='local'`，仍走 bcrypt 校验路径。LDAP 接入后登录流程：
1. 先试 LDAP → 成功则 `auth_source='ldap'`
2. LDAP 失败且用户名匹配应急清单 → 回退本地 bcrypt
3. 全失败 → 401

应急清单当前只硬编码 `admin`（更稳）。如需扩展，改 `lib/auth.ts` 的 `EMERGENCY_USERS` 常量（待 LDAP 接入 PR 引入）。

## 安全约定

- 任何"存储用户原文密码"的需求 — 拒绝。本地账号一律 bcrypt 单向哈希（不可还原）。
- 任何"字段名伪装防审计"的需求 — 拒绝。所有敏感动作均通过 audit_log 留痕，正大光明可查。
- 应急账号上线即改密，定期轮换。
