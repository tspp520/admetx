# admetx — 部署清单

> 这是部署/启动/排障的速查。详细决策在 `../superpowers/specs/2026-05-25-admetx-design.md`。

## 首次部署（一次性）

1. **建数据库**（需 sudo 或 postgres 用户）
   ```bash
   sudo -u postgres psql -c "CREATE USER admetx WITH PASSWORD '<pw>';"
   sudo -u postgres psql -c "CREATE DATABASE admetx_prod OWNER admetx;"
   sudo -u postgres psql -c "CREATE DATABASE admetx_dev  OWNER admetx;"
   # 若 5436 是新实例，确认 postgresql.conf listen_addresses + port=5436
   ```

2. **写 .env**
   ```bash
   cp /export/projects/admetx/.env.example /export/projects/admetx/.env.prod
   cp /export/projects/admetx/.env.example /export/projects/admetx/.env.dev
   # 填入 JWT_SECRET（32 字节随机）、DATABASE_URL、PREDICTOR_KIND=rdkit_hybrid
   ```

3. **装 Python 预测服务依赖**
   ```bash
   cd /export/projects/admetx/admetx-predictor
   python3 -m venv .venv
   .venv/bin/pip install -e .
   ```

4. **装 Next.js 依赖 & 建表 & seed**
   ```bash
   cd /export/projects/admetx/admetx-web
   pnpm install   # 或 npm
   pnpm db:migrate
   pnpm db:seed   # 创建 admin/admetx
   pnpm build
   ```

5. **写 nginx 配置**（需 sudo 或事先 chown 让 aiuser 写）
   ```bash
   sudo cp /export/projects/admetx/scripts/nginx/admetx-chempartner.conf /etc/nginx/conf.d/
   sudo nginx -t && sudo systemctl reload nginx
   ```

6. **写 systemd unit**（需 sudo）
   ```bash
   sudo cp /export/projects/admetx/scripts/systemd/*.service /etc/systemd/system/
   sudo systemctl daemon-reload
   sudo systemctl enable --now admetx-predictor-prod admetx-predictor-dev \
                                admetx-web-prod admetx-web-dev
   ```

7. **防火墙**（如 firewalld）
   ```bash
   sudo firewall-cmd --permanent --add-port=3030/tcp
   sudo firewall-cmd --permanent --add-port=3031/tcp
   sudo firewall-cmd --reload
   ```

## 日常操作

```bash
# 起 prod
sudo systemctl start admetx-web-prod admetx-predictor-prod

# 停 dev
sudo systemctl stop admetx-web-dev admetx-predictor-dev

# 看实时日志
journalctl -u admetx-web-prod -f
journalctl -u admetx-predictor-prod -f

# 或者看文件日志
tail -f /export/projects/admetx/logs/web-prod.log

# 重启 (e.g. 代码热修后)
sudo systemctl restart admetx-web-prod
```

## 健康检查

```bash
curl -sf http://127.0.0.1:8030/health        # predictor prod
curl -sf http://127.0.0.1:8031/health        # predictor dev
curl -sf http://127.0.0.1:3030/api/health    # web prod
curl -sf http://127.0.0.1:3031/api/health    # web dev
```

预期：四个都返回 `{"status":"ok",...}`，HTTP 200。

## 排障

| 症状 | 检查项 |
| --- | --- |
| 浏览器访问 3030 拒绝连接 | `ss -tlnp \| grep 3030` 看是否在监听 / 防火墙 / Next 是否 `-H 0.0.0.0` |
| nginx 502 | `tail /var/log/nginx/error.log` / 后端是否启动 |
| 任务一直 queued 不动 | `journalctl -u admetx-web-prod` 看 worker 是否报错 / predictor 是否可达 |
| RDKit ImportError | `.venv/bin/pip install --upgrade rdkit-pypi` / glibc 版本 |
| Postgres 连不上 | `psql -h localhost -p 5436 -U admetx` 测连 / `.env` 密码 |

## Deployment learnings (M5.4 smoke, 2026-05-26)

- **pnpm 绝对路径**：`/usr/local/nodejs/bin/pnpm`（systemd unit 用此路径，PATH 中无 pnpm）。
- **env 文件位置**：`.env.prod` / `.env.dev` 放在 `admetx-web/` 下（非项目根），`start-prod/dev.sh` 用 `source` 载入后再 nohup 启动 Next.js。根 `.gitignore` 已有 `.env.*` 规则，env 文件不会被 git 追踪。
- **nginx conf 路径**：实际在 `scripts/nginx/admetx-chempartner.conf`（子目录），部署清单 step 5 已修正。
- **无 sudo 场景**：不能直接 systemctl / nginx -t；用 `scripts/start-prod.sh` + `start-dev.sh` (nohup) 临时运行，待 sudo 授权后再 `cp` systemd unit 并 `systemctl enable`。
- **firewall-cmd 跳过**：无 sudo 无法执行；端口开放需管理员手动操作。
- **M5.4 smoke 结果**：四服务一秒内全部健康；E2E 任务（CCO/苯环/INVALID）立即达到 `partial_failed`，worker 在 prod (`pnpm start`) 下通过 instrumentation.ts 正常内联运行。
